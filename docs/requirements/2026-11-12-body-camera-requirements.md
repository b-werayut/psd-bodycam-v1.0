## 1. ภาพรวมโครงการ (Project Overview)

ต้องการพัฒนาระบบ **Body Camera Management System** สำหรับบริหารจัดการกล้อง Body Camera ที่ใช้งานโดยหัวหน้าทีมปฏิบัติงานภาคสนาม โดยระบบจะเชื่อมโยงข้อมูลการปฏิบัติงานกับระบบ **Smart Booking** เพื่อให้สามารถตรวจสอบภาพถ่ายทอดสด วิดีโอย้อนหลัง และข้อมูลพิกัด GPS ของกล้องที่ใช้งานระหว่างปฏิบัติงานได้

ระบบประกอบด้วย 2 ส่วนหลัก ได้แก่

1. **Web Application** — สำหรับแอดมินฝ่ายความปลอดภัยและผู้จัดการแผนก/ฝ่ายความปลอดภัย
2. **Mobile Application** — สำหรับหัวหน้าทีมปฏิบัติงานภาคสนามที่ได้รับมอบหมายกล้อง Body Camera

**วัตถุประสงค์หลัก**

- บันทึกวิดีโอระหว่างการปฏิบัติงานภาคสนาม
- เชื่อมโยงวิดีโอและข้อมูลการปฏิบัติงานเข้ากับใบงานจาก Smart Booking
- ตรวจสอบการปฏิบัติงานผ่านภาพถ่ายทอดสดจาก Body Camera
- ตรวจสอบวิดีโอย้อนหลังโดยอ้างอิงใบงาน
- ติดตามตำแหน่ง GPS ของกล้องแบบ Real-time
- บริหารจัดการผู้ใช้งานและสิทธิ์การเข้าถึงข้อมูล

## 2. การเชื่อมต่อกับ Smart Booking (System Integration)

ระบบ Body Camera จะใช้ข้อมูลใบงานจาก **Smart Booking เป็นแหล่งข้อมูลอ้างอิงหลัก**

จากการหารือร่วมกับทีมพัฒนาระบบ Smart Booking ได้ข้อสรุปว่าจะพัฒนาระบบให้สามารถรับส่งรายละเอียดข้อมูลระหว่างกันได้

### Requirements

- เชื่อมต่อกับ Smart Booking เพื่อรับข้อมูลใบงาน
- สามารถอ้างอิงใบงานจาก Smart Booking ภายในระบบ Body Camera ได้
- วิดีโอที่บันทึกต้องสามารถเชื่อมโยงกับใบงานที่เกี่ยวข้องได้
- ผู้ใช้งานสามารถตรวจสอบได้ว่าวิดีโอแต่ละรายการเกี่ยวข้องกับใบงานใด
- ออกแบบการรับส่งข้อมูลระหว่างสองระบบให้รองรับการพัฒนาและขยายระบบในอนาคต
- ไม่สร้างระบบ Booking ใหม่ภายใน Body Camera แต่ให้ใช้ Smart Booking เป็นระบบหลักในการจัดการใบงาน

รายละเอียด API, รูปแบบการรับส่งข้อมูล และเงื่อนไขการเชื่อมโยงใบงานจะต้องออกแบบและตกลงร่วมกับทีม Smart Booking เพิ่มเติม

## 3. Web Application Requirements

### 3.1 กลุ่มผู้ใช้งาน

ผู้ใช้งานหลักของ Web Application ได้แก่

- แอดมินฝ่ายความปลอดภัย (Safety Administrator)
- ผู้จัดการแผนก/ฝ่ายความปลอดภัย (Safety Manager)

โดยกำหนดสิทธิ์การเข้าถึงฟังก์ชันตามบทบาทผู้ใช้งาน (Role-Based Access Control)

### 3.2 ฟังก์ชันหลัก (Core Features)

**1. Live Streaming**

- แสดงภาพถ่ายทอดสดจากกล้อง Body Camera
- สามารถตรวจสอบกล้องที่กำลังใช้งานได้
- แสดงข้อมูลใบงานจาก Smart Booking ที่เกี่ยวข้องกับการปฏิบัติงาน
- ออกแบบหน้าจอสำหรับตรวจสอบภาพสดจากกล้องหลายตัว

**2. Video Playback**

- แสดงรายการวิดีโอย้อนหลังที่บันทึกจาก Body Camera
- รองรับการเล่นวิดีโอย้อนหลัง
- แสดงข้อมูลใบงานที่เกี่ยวข้องกับวิดีโอแต่ละรายการ
- สามารถค้นหาและตรวจสอบวิดีโอตามใบงานได้
- ออกแบบให้สามารถตรวจสอบข้อมูลการบันทึกตามวันและเวลาได้

**3. Real-time GPS Monitoring**

- แสดงข้อมูลพิกัด GPS ปัจจุบันของ Body Camera
- แสดงตำแหน่งของกล้องผ่านแผนที่
- รองรับการอัปเดตพิกัดแบบ Real-time
- เชื่อมโยงตำแหน่งกับกล้องและผู้รับผิดชอบที่เกี่ยวข้อง

**4. User Management**

- จัดการบัญชีผู้ใช้งานภายในระบบ
- เพิ่ม แก้ไข และจัดการสถานะผู้ใช้งาน
- กำหนด Role และ Permission
- จำกัดการเข้าถึงข้อมูลตามสิทธิ์ของผู้ใช้งาน
- การจัดการผู้ใช้งานดำเนินการโดย Administrator

### 3.3 Optional Features (ยังไม่ยืนยัน)

**1. GPS History Tracking**

- แสดงประวัติตำแหน่ง GPS ย้อนหลัง
- แสดงเส้นทางที่กล้องเดินทางผ่านบนแผนที่
- รองรับการตรวจสอบเส้นทางตามช่วงเวลา
- สามารถเชื่อมโยงประวัติเส้นทางเข้ากับใบงานที่เกี่ยวข้อง

**2. Two-way Audio Communication**

- รองรับการสื่อสารด้วยเสียงระหว่าง Web Application และ Body Camera
- ผู้ใช้งานบนเว็บไซต์สามารถพูดสื่อสารไปยังกล้องได้
- รองรับการรับเสียงจากกล้องกลับมายังเว็บไซต์

หมายเหตุ: ทั้งสองฟังก์ชันเป็น Optional และยังไม่ได้รับการยืนยันให้รวมอยู่ในขอบเขตการพัฒนาระยะแรก ต้องประเมินความเป็นไปได้จากอุปกรณ์และระบบที่เกี่ยวข้องก่อน

## 4. Mobile Application Requirements

### 4.1 กลุ่มผู้ใช้งาน

Mobile Application ใช้งานโดย **หัวหน้าทีมปฏิบัติงานภาคสนาม (Team Leader)** เป็นหลัก

เนื่องจากกล้อง Body Camera มีการใช้งานเฉพาะหัวหน้าทีม จึงไม่จำเป็นต้องออกแบบให้สมาชิกทีมทุกคนเป็นผู้ใช้งานหลักของแอปพลิเคชัน

### 4.2 ฟังก์ชันหลัก

**1. Live Streaming**

- หัวหน้าทีมสามารถดูภาพถ่ายทอดสดจากกล้อง Body Camera ที่เกี่ยวข้องกับตนเอง
- ออกแบบหน้าจอสำหรับตรวจสอบภาพสดให้เหมาะกับการใช้งานบนมือถือ

**2. Booking Job Details**

- แสดงรายละเอียดใบงานจาก Smart Booking
- แสดงข้อมูลใบงานที่เกี่ยวข้องกับการปฏิบัติงานของหัวหน้าทีม
- ออกแบบให้ผู้ใช้งานสามารถเข้าถึงรายละเอียดใบงานได้สะดวก

### 4.3 ฟังก์ชันที่ไม่อยู่ในขอบเขต Mobile Application

ฟังก์ชันต่อไปนี้กำหนดให้ใช้งานผ่าน Web Application สำหรับ Administrator เป็นหลัก

- Video Playback (วิดีโอย้อนหลัง)
- GPS Monitoring
- Camera On/Off Status Monitoring
- User Management

Mobile Application จะเน้นเฉพาะ **Live Streaming และรายละเอียดใบงาน** เพื่อให้สอดคล้องกับการปฏิบัติงานจริงของหัวหน้าทีม

## 5. ความสัมพันธ์ระหว่าง Body Camera และ Smart Booking

ต้องออกแบบให้สามารถเชื่อมโยงข้อมูลหลักดังต่อไปนี้

- ข้อมูลใบงานจาก Smart Booking
- ข้อมูลผู้รับผิดชอบงาน
- ข้อมูลกล้อง Body Camera
- ข้อมูลการถ่ายทอดสด
- ข้อมูลการบันทึกวิดีโอ
- ข้อมูลพิกัด GPS
- ข้อมูลวันและเวลาที่เกี่ยวข้องกับการปฏิบัติงาน

**ตัวอย่าง Workflow เบื้องต้น**

1. มีการสร้างใบงานในระบบ Smart Booking
2. ระบบ Body Camera ได้รับข้อมูลใบงานจาก Smart Booking
3. หัวหน้าทีมเข้าถึงรายละเอียดใบงานที่เกี่ยวข้องผ่าน Mobile Application
4. ระหว่างปฏิบัติงาน มีการใช้งานกล้อง Body Camera เพื่อถ่ายทอดสดและบันทึกวิดีโอ
5. ระบบเชื่อมโยงวิดีโอที่บันทึกเข้ากับใบงานที่เกี่ยวข้อง
6. แอดมินฝ่ายความปลอดภัยหรือผู้จัดการสามารถตรวจสอบ Live Streaming ผ่าน Web Application
7. ผู้ใช้งานที่ได้รับสิทธิ์สามารถตรวจสอบ Video Playback และ GPS ผ่านเว็บไซต์
8. สามารถตรวจสอบย้อนหลังได้ว่าวิดีโอแต่ละรายการเกี่ยวข้องกับใบงานใด

หมายเหตุ: Workflow นี้เป็นแนวทางเบื้องต้น ต้องออกแบบเพิ่มเติมในส่วนการเชื่อมโยงใบงานกับกล้อง การเริ่มและหยุดบันทึก รวมถึงเงื่อนไขกรณีเกิดข้อผิดพลาด

## 7. สิ่งที่ต้องการให้ AI ช่วยออกแบบและพัฒนา

จาก Requirements ทั้งหมดข้างต้น ให้ทำหน้าที่เป็น **Senior Software Architect และ Full-stack Engineer** เพื่อวางแผนและออกแบบระบบ Body Camera Management System สำหรับใช้งานจริงในระดับ Production

ต้องการผลลัพธ์ดังต่อไปนี้

### 7.1 System Architecture

- ออกแบบภาพรวม Architecture ของ Web Application, Mobile Application, Backend และ Database
- ออกแบบการเชื่อมต่อกับ Smart Booking
- ออกแบบการรับส่งข้อมูล Live Streaming, Playback และ GPS
- เสนอเทคโนโลยีที่เหมาะสม พร้อมเหตุผล
- แสดง Architecture Diagram และ Data Flow

### 7.2 Database Design

- ออกแบบ Database Schema
- ออกแบบความสัมพันธ์ระหว่าง User, Device, Booking Job, Recording และ GPS
- พิจารณาการจัดเก็บข้อมูลอ้างอิงใบงานจากระบบภายนอก
- ออกแบบให้รองรับข้อมูลย้อนหลังและปริมาณข้อมูลที่เพิ่มขึ้น
- แสดง ER Diagram

### 7.3 API Design

- ออกแบบ REST API สำหรับ Web และ Mobile
- ออกแบบ API Integration กับ Smart Booking
- ออกแบบช่องทางรับส่งข้อมูล Real-time
- ออกแบบ Authentication และ Authorization
- ระบุ API Endpoint, Request, Response และ Error Handling

### 7.4 UI/UX Design

- ออกแบบ Sitemap ของ Web Application และ Mobile Application
- แยกหน้าจอตามสิทธิ์ผู้ใช้งาน
- ออกแบบ User Flow สำหรับการติดตามภาพสดและตรวจสอบใบงาน
- ออกแบบ Dashboard และหน้าจอที่เหมาะกับการใช้งานจริง
- เน้น Modern, Minimal, Professional Enterprise UI

### 7.5 Development Planning

- จัดลำดับการพัฒนาโดยเน้น Core Features ก่อน
- แยก MVP และ Optional Features ให้ชัดเจน
- เสนอ Project Structure
- วางแผน Implementation เป็น Phase
- ระบุความเสี่ยงด้าน Streaming, Storage, GPS และการเชื่อมต่อ Smart Booking
- เสนอแนวทาง Security, Logging, Monitoring และ Deployment
