## 1. ระบบนี้คืออะไร

ระบบติดตามการใช้กล้อง Bodycam ของพนักงานภาคสนาม: ดูตำแหน่งและสถานะกล้อง, ดูภาพสดและพูดคุย (talk), ดูย้อนหลังและดาวน์โหลดหลักฐาน MP4 และผูกช่วงเวลาที่กล้องเปิดเข้ากับ**ใบงานจาก Smart Booking อัตโนมัติ**

- **Web** — ผู้ดูแลระบบ, ผู้ดูแลบริษัท, ศูนย์ควบคุม/ผู้จัดการแผนก, ผู้ดูข้อมูล
- **Mobile app** — หัวหน้าทีมภาคสนามเท่านั้น (ดูสดกล้องของตัวเอง + รายละเอียดใบงาน)

### ศัพท์ที่ต้องใช้ให้ตรงกันทุกหน้าจอ

| คำบนจอ | ความหมาย |
|---|---|
| Bodycam / กล้อง | กล้องติดตัว 1 เครื่อง |
| Session | ช่วงเวลาที่กล้อง 1 ตัวเปิดต่อเนื่อง ผูกกับใบงานได้ 0–1 ใบ |
| ใบงาน | งาน 1 งานจาก Smart Booking (1 งาน Booking = 1 ใบงาน) · สถานะเปลี่ยนตาม check-in / check-out ใน Booking |
| งานจาก Booking | ข้อมูลดิบที่ Smart Booking ส่งมา (เลข Booking, DO, SH, เวลา check-in/out) |
| หลักฐาน | วิดีโอย้อนหลังของกล้องในช่วงเวลาของใบงาน + ไฟล์ MP4 ที่ export |
| ฐาน/จุดชาร์จ | จุดที่กล้องวางชาร์จ — กล้องเปิดที่ฐานไม่นับเป็นงาน |
| Live wall | จอรวมภาพสดหลายกล้อง (1/4/6/9/16 ช่อง) |

### สิ่งที่ระบบ "ไม่มี" — ห้ามออกแบบปุ่มหรือหน้าเหล่านี้

- สร้าง / ปิด / เปิดใหม่ / ยกเลิก / void / merge ใบงาน (ใบงานมาจาก Booking เท่านั้น)
- ผูก / ยกเลิกผูก session กับใบงานด้วยมือ · คิวตรวจสอบ · classify session
- หน้าผูกกล้องกับทีม (การผูกมาจาก Booking)
- ปุ่ม check-in / check-out (ทำใน Booking app)
- เมนู "คิวตรวจสอบ" ที่ยังค้างใน `client/src/app/nav.ts` — เลิกใช้แล้ว (DL33) ไม่ต้องออกแบบ

### 2.3 ขนาดและระยะ

- Spacing: 4 / 8 / 12 / 16 / 24 / 32 เท่านั้น
- มุม: เมนู 6px · การ์ด, input, ปุ่ม, แถวตาราง 8px · dialog 12–16px · วงกลมเฉพาะจุดสถานะ, avatar, pill
- Shell: sidebar 232px (ยุบ 72px) · header 56px · เนื้อหากว้างสุด 1600px กึ่งกลาง · padding หน้า 24px (จอกว้าง) / 20px (แท็บเล็ต) / 16px (มือถือ)
- เมนู sidebar สูง 38px (desktop) · รายการที่เลือก = พื้น cobalt ตัวอักษรขาว
- Input / ปุ่ม สูง 44px · ตาราง: หัว 40px, padding cell 8×12, แถวสองบรรทัด 52–60px
- เงา: การ์ดที่วางนิ่งไม่มีเงา · เงาเฉพาะ menu (medium), dialog/toast (high)

### 2.4 กติกาที่ต้องรักษา

1. สีคู่ข้อความเสมอ — ห้ามสื่อสถานะด้วยสีอย่างเดียว
2. cobalt ใช้เฉพาะ action / selection / link / focus
3. หนึ่งหน้า (หรือหนึ่ง dialog) มีปุ่ม primary ปุ่มเดียว
4. ปุ่ม disabled ต้องบอกเหตุผล (tooltip หรือข้อความใต้ปุ่ม)
5. เครื่องมือต่อแถว 3 อันขึ้นไป ยุบอันรองเข้า `•••` · ปุ่มลบแยกจากปุ่มปกติ
6. ตารางกว้างเกินให้ scroll ในกรอบตาราง ห้ามทำทั้งหน้าเลื่อนแนวนอน
7. skeleton ตาม layout จริง · "ยังไม่มีข้อมูล" ≠ "ไม่พบตามตัวกรอง"
8. สำเร็จ = toast · ล้มเหลว = toast + Alert ค้างบนหน้า
9. เป้ากดอย่างน้อย 44px บนจอสัมผัส
10. เวลาแสดงเป็นเวลาไทย (Asia/Bangkok) รูปแบบ `17 พ.ย. 2569 14:05`

| `ADMIN` | ผู้ดูแลระบบ (Super admin) | Web | ทั้งหมด | ทำได้ทุกอย่าง รวม Audit, ตั้งค่า, สิทธิ์ของ role, การเชื่อมต่อ Booking, จัดการ/ sync กล้อง |

### 3.1 `COMPANY_ADMIN` — กติกาที่ต้องเห็นในแบบ

**ทำได้**
- ทุกเมนูปฏิบัติการเหมือน `OPERATOR` แต่เห็นข้อมูลทั้งบริษัท
- จัดการพนักงาน, แผนก (`org:manage`) และทีม (`teams:manage`)
- จัดการบัญชีผู้ใช้ role `COMPANY_ADMIN`, `OPERATOR`, `VIEWER`, `TEAM_LEADER`: สร้าง, แก้ไข, ตั้งรหัสผ่านใหม่, ระงับ, คืนสิทธิ์, ลบ
- เปิดดูตาราง "บทบาทและสิทธิ์" ได้แบบ**อ่านอย่างเดียว** เพื่อรู้ว่าแต่ละ role ทำอะไรได้ก่อนกำหนดให้ผู้ใช้

**ทำไม่ได้** (ไม่เห็นเมนู · เปิด URL ตรงเห็นการ์ด "ไม่มีสิทธิ์เข้าถึงหน้านี้")
- ประวัติการใช้งาน (Audit log)
- ตั้งค่าระบบ (รวมสิทธิ์ภาพสดต่อ role)
- แก้ตารางสิทธิ์ของ role
- สถานะการเชื่อมต่อ (Integration กับ Smart Booking)
- จัดการ / sync กล้อง และแก้ไขฐาน/จุดชาร์จ (ดูได้อย่างเดียว)
- แก้ ระงับ หรือลบบัญชี `ADMIN` · เลือก role `ADMIN` ให้ใคร (กันยกระดับสิทธิ์ตัวเอง)
- ระงับหรือลบบัญชีตัวเอง (กติกาเดิมของทุก role)

**การแจ้งเตือน**: ได้รับ alert ปฏิบัติการเหมือน `OPERATOR` (กล้องไม่ผูกทีม, กล้อง offline ระหว่างงาน, ใบงานปิดอัตโนมัติ, Booking ยกเลิกแต่มีวิดีโอ, งานเปลี่ยนหลังปิด, วิดีโอนอกงาน, ใบงานไม่มี check-out) · alert ระบบ/การเชื่อมต่อ (Booking ค้าง, dead letter, mapping issue, กล้องหายจาก DSS, Booking เงียบ) ส่งให้ `ADMIN` เท่านั้น
