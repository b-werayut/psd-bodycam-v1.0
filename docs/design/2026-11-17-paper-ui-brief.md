# PSD Body worn camera — Brief สร้างหน้าจอตัวอย่างใน Paper

> สำหรับ agent ที่สร้างภาพหน้าจอในไฟล์ Paper **"PSD Body worn camera — แบบ UI สำหรับยืนยันดีไซน์"** (ชื่อไฟล์เดิม "PSD Sentinel — แบบ UI สำหรับยืนยันดีไซน์" — ถ้ายังเป็นชื่อเดิมให้เปลี่ยนเป็นชื่อนี้)
> ภาพทั้งหมดใช้ให้ลูกค้าดูและยืนยัน UX/UI ของระบบ

---

## 0. วิธีทำงาน (อ่านก่อนเริ่ม)

### 0.1 เป้าหมาย

สร้างภาพหน้าจอตัวอย่างของระบบ **PSD Body worn camera** ให้ครบทุกเมนู เพื่อให้ลูกค้าเห็นภาพการใช้งานจริงและยืนยันได้ว่า **หน้าตา เมนู ข้อมูลที่แสดง และสิทธิ์ของแต่ละบทบาท** ถูกต้อง

ระบบนี้ใช้งานโดย**ฝ่าย จป. ของบริษัท** ฝ่ายเดียว — ไม่มีการแบ่งข้อมูลตามแผนก ทุกบทบาทบน web เห็นข้อมูลทั้งบริษัท ต่างกันแค่ฟังก์ชันที่ใช้ได้

### 0.2 กติกาภาพสำหรับลูกค้า

- ทุกหน้าและทุกเมนูต้องดูเหมือนระบบที่ใช้งานได้จริง — **ห้าม** มีป้าย "ยังไม่เปิดใช้งาน", "coming soon", "เร็ว ๆ นี้", รหัสระยะการพัฒนา หรือข้อความว่าส่วนไหนทำเสร็จแล้ว
- แสดงเฉพาะ 4 บทบาทใน §4 และเมนู 10 รายการใน §5.1 เท่านั้น — ห้ามเพิ่มบทบาท เมนู หรือหน้าอื่น (§1.2)
- ห้ามมีชื่อไฟล์โค้ด, path ของระบบ, ชื่อ API, รหัสสิทธิ์ภาษาอังกฤษ (เช่น `users:manage`) หรือศัพท์หลังบ้านบนภาพ
- **ชื่อระบบคือ "PSD Body worn camera"** ทุกจุด (หน้าเข้าสู่ระบบ, sidebar, หน้าใช้งานผ่านแอปมือถือ, แอปมือถือ, ชื่อแท็บ) — **ห้ามใช้ชื่อ "PSD Sentinel"** และไม่ต้องมีคำโปรยภาษาอังกฤษใต้ชื่อ (เช่น "Body Camera Management")
- ข้อความบนจอเป็น**ภาษาไทย** · คงคำอังกฤษที่ผู้ใช้คุ้นอยู่แล้ว: Bodycam, Live, Booking, Microsoft, Entra, MP4
- **ข้อความบนจอไม่บอกที่มาของข้อมูล** — สถานะ หัวข้อ คำอธิบาย เหตุผล และแจ้งเตือน ไม่เขียน "จาก Booking", "โดย Booking", "ใน Booking" หรือ "Smart Booking" (เช่น สถานะ "ยกเลิก" ไม่ใช่ "ยกเลิกโดย Booking") · คงคำว่า Booking เฉพาะชื่อช่องที่เป็นเลขอ้างอิง: "เลข Booking", "รหัสอ้างอิง Booking" และช่องค้นหา "เลขใบงาน / Booking / DO / SH"
- ใช้**ข้อมูลตัวอย่างชุดเดียวกัน** (§3) ทุก frame เพื่อให้ภาพเล่าเรื่องต่อกันได้ · ห้ามใช้ข้อมูลจริงของบุคคลหรือบริษัทอื่น
- อธิบายพฤติกรรมด้วย callout สั้นภาษาไทยข้าง frame ได้ (เช่น "ไฟล์ที่ไม่ผูกใบงานติดป้ายสีเหลือง") · callout วางนอกหน้าจอ ไม่ทับ UI
- ชื่อ frame = ชื่อหน้าจอ + กรณี เช่น `ใบงาน · ตาราง`, `วิดีโอย้อนหลัง · ค้นรายกล้อง (มีไฟล์ที่ไม่ผูกใบงาน)`, `ผู้ใช้ระบบ · มุมมองผู้ดูแลบริษัท`

### 0.3 โครง page ในไฟล์ Paper

### 0.4 ขนาด frame

- Web: **1440×1024** (จอศูนย์ควบคุม) เป็นหลัก
- Web responsive: ทำ **390×844** อย่างน้อย 2 หน้า (ใบงาน และ ผู้ใช้ระบบ)
- Dark mode: ทำอย่างน้อย 2 หน้า (แดชบอร์ด และ ภาพสดหลายจอ)
- แอปมือถือ: **390×844**

### 0.5 State ที่ต้องมี

ทุกหน้าที่มีข้อมูลให้ทำ frame ปกติ (มีข้อมูลเต็ม) เป็นหลัก แล้วเพิ่ม state ที่ระบุไว้ในแต่ละหน้า · รูปแบบ state กลาง:

- **กำลังโหลด** — skeleton ตาม layout จริง (ไม่ใช้ spinner กลางจอ)
- **ยังไม่มีข้อมูล** — ไอคอน + ข้อความ + ปุ่มทำต่อ (ถ้ามี)
- **ไม่พบตามตัวกรอง** — ข้อความ + คำแนะนำให้ล้างตัวกรอง (คนละแบบกับ "ยังไม่มีข้อมูล")
- **โหลดไม่สำเร็จ** — บอกว่าส่วนไหนโหลดไม่ได้ + ปุ่ม "ลองใหม่"

### 0.7 สิ่งที่ต้องแก้ใน frame ที่ทำไว้แล้ว (รอบก่อน)

ไฟล์ Paper มี frame จากรอบก่อนอยู่แล้ว — **แก้ frame เดิม** ตามรายการนี้ก่อน แล้วค่อยสร้าง frame ที่ยังไม่มี

1. **จัด page ใหม่** ตาม §0.3 (7 page) · ย้าย frame เดิมเข้า page ที่ถูกต้อง
2. **บทบาทเหลือ 4** (ผู้ดูแลบริษัท · ผู้ปฏิบัติการ · ผู้ดูข้อมูล · หัวหน้าทีม) — ลบการ์ด, sidebar, คอลัมน์ในตารางสิทธิ์, ผู้ใช้ตัวอย่าง admin และข้อความทุกจุดที่เป็นของบทบาท "ผู้ดูแลระบบ"
3. **Sidebar ทุก frame** เปลี่ยนเป็นเมนู 10 รายการตาม §5.1 และ §5.2:
   - ลบ: Live, หลักฐาน, Tracking sessions, บันทึกวิดีโอ, Bodycam, ทีม, แผนก, ฐาน/จุดชาร์จ, สถานะการเชื่อมต่อ, ประวัติการใช้งาน, ตั้งค่า
   - เพิ่ม: ภาพสดหลายจอ, ใบงาน, วิดีโอย้อนหลัง, ผู้ใช้จาก Entra
   - เปลี่ยนชื่อ: "การแจ้งเตือน" → แจ้งเตือน · "ผู้ใช้และสิทธิ์" → ผู้ใช้ระบบ
   - กลุ่มเมนูเป็น ภาพรวม / ปฏิบัติงาน / ผู้ใช้และพนักงาน / ระบบ
   - ผู้ดูข้อมูล: เห็นเฉพาะ แดชบอร์ด, ใบงาน, แผนที่ติดตาม, ประวัติเส้นทาง, พนักงาน, แจ้งเตือน
4. **ลบ frame** ของหน้าที่ไม่อยู่ในภาพชุดนี้: แผนก, Bodycam (รายการ/รายละเอียด/ซิงก์), ทีม, ฐาน/จุดชาร์จ, สถานะการเชื่อมต่อ, Tracking sessions, บันทึกวิดีโอ, ประวัติการใช้งาน, ตั้งค่าระบบ
5. **เอาแผนกออก** จากทุกตาราง ฟอร์ม และตัวกรอง: หน้าพนักงาน (คอลัมน์ + ตัวกรอง + ช่องในฟอร์ม), หน้าผู้ใช้ระบบ (คอลัมน์ + ช่องในฟอร์ม), เมนูผู้ใช้บน header
6. **หน้า "หลักฐาน" เดิม** เปลี่ยนชื่อเป็น **วิดีโอย้อนหลัง** และเปลี่ยนจากตารางใบงานเป็นหน้าค้นรายกล้อง (§9.3) · dialog ดูวิดีโอเดิมใช้กับปุ่ม ดูย้อนหลัง ของใบงาน แต่แสดงเฉพาะไฟล์ในช่วงใบงาน และตัดป้าย "อยู่ในช่วงใบงาน" ออก (§9.4)
7. **สร้างใหม่**: ใบงาน + รายละเอียดใบงาน (§9.1–9.2) · ผู้ใช้จาก Entra (§10.5) · ภาพสดหลายจอแบบมีรายการกล้องและใบงานบนแต่ละช่อง (§8.1)
8. **ข้อมูลตัวอย่าง**: เปลี่ยนให้ตรง §3 ทุก frame (ไม่มีคอลัมน์แผนก และไม่มีผู้ใช้ admin ในตารางผู้ใช้)
9. **ผู้ดูแลบริษัทใช้ฟังก์ชันหลักได้ครบ** — การ์ดบทบาทต้องขึ้นต้นด้วยงานติดตามกล้อง / ภาพสด / ใบงาน / วิดีโอย้อนหลัง ก่อนงานจัดการผู้ใช้ (ข้อความตาม §6 ข้อ 1) · sidebar ของผู้ดูแลบริษัทมีครบ 10 เมนู · หน้าปฏิบัติงานที่วาดด้วยมุมมองผู้ดูแลบริษัทมีปุ่มครบเหมือนผู้ปฏิบัติการ (ดูสด, talk, ดูย้อนหลัง, ดาวน์โหลด, รับทราบ, ปิดเรื่อง)
10. **ชื่อระบบ**: เปลี่ยน "PSD Sentinel" เป็น **"PSD Body worn camera"** ทุก frame — หน้าเข้าสู่ระบบ, sidebar (ทั้งแบบเต็มและแบบยุบ), หน้าใช้งานผ่านแอปมือถือ, แอปมือถือ · ลบคำโปรย "Body Camera Management" ใต้ชื่อ · เปลี่ยนชื่อไฟล์ Paper ตามหัวเอกสารนี้
11. **แจ้งเตือน**: ใช้ตัวอย่างเรื่องกล้องและวิดีโอตาม §11.1 ทั้งบนแดชบอร์ดและหน้าแจ้งเตือน · แยกปุ่ม "รับทราบ" กับ "ปิดเรื่อง" รายรายการตามสถานะและสิทธิ์
12. **แอปมือถือหัวหน้าทีม**: ปรับเลย์เอาต์หน้า 07 ตามชุดภาพ PSD BWC Mockup และขอบเขต §12
13. **แอปมือถือเหลือแค่ดูสด + ใบงาน + แจ้งเตือนใบงาน** (หน้า 07):
    - ลบ frame: รายการวิดีโอย้อนหลัง · ดูวิดีโอย้อนหลัง — หัวหน้าทีมไม่มีวิดีโอย้อนหลัง
    - คง frame "ใส่รหัส PIN" ไว้ต่อจากหน้าเข้าสู่ระบบ
    - ลบจุดสถานะ / ป้าย ออนไลน์ · ออฟไลน์ · ไม่ทราบสถานะ ของกล้องในทุกหน้าของแอป (หน้าแรก, กล้องของฉัน, รายละเอียดใบงาน, ดูสด) — การดูสถานะกล้องอยู่บน web
    - ปุ่ม "ดูสด" แสดงกับกล้องของทีมทุกตัว · กล้องออฟไลน์ไปบอกในหน้าดูสดแทน (§12)
    - แถบนำทางด้านล่างคง 4 จุดเดิม ไม่มีจุดวิดีโอ
14. **dialog ดูสดทุก frame บน web มีปุ่ม talk** (§8.2): dialog ที่เปิดจากตารางใบงาน, หน้ารายละเอียดใบงาน และการ์ดกล้องบนแผนที่ติดตาม ต้องมี pill ไมค์แบบเดียวกับภาพสดหลายจอ · เพิ่ม frame talk กำลังพูด · เปิดจากแผนที่ · มีผู้ใช้อื่นกำลังพูด
15. **ตัดข้อความที่บอกว่ามาจาก Booking** (§0.2) ทุก frame: "ยกเลิกโดย Booking" → "ยกเลิก" (ตารางใบงาน, แถบสถานะบนแดชบอร์ด) · "ใบงานจาก Smart Booking และกล้องที่ใช้ในแต่ละงาน" → "ใบงานและกล้องที่ใช้ในแต่ละงาน" · แถบ "ได้รับข้อมูลจาก Smart Booking ล่าสุดเมื่อ …" → "ได้รับข้อมูลใบงานล่าสุดเมื่อ …" · การ์ด "รับข้อมูล Booking ล่าสุด" → "รับข้อมูลใบงานล่าสุด" · panel "ข้อมูล Booking" → "ข้อมูลงาน" (ตัดแถว "สถานะใน Booking") · "Booking ระบุกล้อง … ในใบงานนี้" → "ใบงานนี้ระบุกล้อง …" · คอลัมน์ "ทีม (จาก Booking)" → "ทีม" · คำอธิบายแจ้งเตือน "Smart Booking ยังไม่ได้ผูกกล้อง…" → "ยังไม่มีทีมหรือใบงานที่ระบุกล้องนี้ ณ เวลาที่ตรวจพบ" · คง "เลข Booking", "รหัสอ้างอิง Booking" และช่องค้นหาไว้

## 1. ระบบนี้คืออะไร

ระบบติดตามการใช้กล้อง Bodycam ของหัวหน้าทีมภาคสนาม: ดูภาพสดจากกล้องหลายตัวพร้อมกันและพูดคุยผ่านกล้อง (talk), ดูตำแหน่งกล้องบนแผนที่และเส้นทางย้อนหลัง, ดูวิดีโอย้อนหลังและดาวน์โหลด MP4 **โดยอ้างอิงใบงานจาก Smart Booking** ซึ่งระบบผูกกับช่วงเวลาที่กล้องเปิดให้อัตโนมัติ

- **Web** — ผู้ดูแลบริษัท, ผู้ปฏิบัติการ, ผู้ดูข้อมูล (ฝ่าย จป.)
- **แอปมือถือ** — หัวหน้าทีมภาคสนามเท่านั้น (ดูสดกล้องของทีม + รายละเอียดใบงาน)

### 1.1 คำที่ต้องใช้ให้ตรงกันทุกหน้าจอ

| คำบนจอ | ความหมาย |
|---|---|
| Bodycam / กล้อง | กล้องติดตัว 1 เครื่อง (รายการกล้องมาจากระบบกล้องโดยอัตโนมัติ) |
| ใบงาน | งาน 1 งานจาก Smart Booking · สถานะเปลี่ยนตาม check-in / check-out ใน Booking |
| ข้อมูลงาน | ข้อมูลที่มากับใบงาน: เลข Booking, DO, SH, เวลา check-in / check-out, สถานที่, ทีม / หัวหน้า, กล้องที่ใช้ |
| ทีม | ทีมภาคสนามตามข้อมูลใน Booking (ไม่มีหน้าจัดการทีมในระบบนี้) |
| ช่วงใบงาน / ปฏิบัติงานจริง | เวลา check-in ถึง check-out ตาม Booking · ยังไม่ check-out = ถึงตอนนี้ |
| ภาพสดหลายจอ | จอรวมภาพสดหลายกล้อง (1 / 4 / 6 / 9 / 16 ช่อง) |
| วิดีโอย้อนหลัง | เลือกกล้องและวันที่ แล้วดูไฟล์ทุกช่วงที่กล้องบันทึกไว้ (บอกว่าเป็นของใบงานไหน หรือยังไม่ผูกใบงาน) + ดาวน์โหลด MP4 |

### 1.2 สิ่งที่ไม่มีในระบบ — ห้ามออกแบบปุ่มหรือหน้าเหล่านี้

- เมนู / หน้า: แผนก, Bodycam (รายการ/จัดการกล้อง), ทีม, ฐาน/จุดชาร์จ, สถานะการเชื่อมต่อ, Tracking sessions, บันทึกวิดีโอรายกล้อง, Live รายกล้องแยกเมนู
- ช่องหรือตัวกรอง "แผนก" ในทุกฟอร์มและตาราง
- สร้าง / ปิด / เปิดใหม่ / ยกเลิก / รวม ใบงาน (ใบงานมาจาก Booking เท่านั้น)
- ผูก / ยกเลิกผูก กล้องกับใบงานหรือทีมด้วยมือ · คิวตรวจสอบ
- ปุ่ม check-in / check-out (ทำในแอป Booking)
- หน้าประวัติการใช้งานและหน้าตั้งค่าระบบ (ไม่อยู่ในภาพชุดนี้)
- ในแอปมือถือ: วิดีโอย้อนหลัง, ดาวน์โหลด MP4, แผนที่ / ประวัติเส้นทาง, talk, สถานะกล้อง (ออนไลน์ / ออฟไลน์), รับทราบ / ปิดเรื่องแจ้งเตือน, จัดการผู้ใช้

### 2.3 ขนาดและระยะ

- Spacing: 4 / 8 / 12 / 16 / 24 / 32 เท่านั้น
- มุม: เมนู 6px · การ์ด, input, ปุ่ม, แถวตาราง 8px · dialog 12–16px · วงกลมเฉพาะจุดสถานะ, avatar, pill
- Shell: sidebar 232px (ยุบ 72px) · header 56px · เนื้อหากว้างสุด 1600px กึ่งกลาง · ระยะขอบหน้า 24px (จอกว้าง) / 20px (แท็บเล็ต) / 16px (มือถือ)
- เมนู sidebar สูง 38px · รายการที่เลือก = พื้น cobalt ตัวอักษรขาว
- Input / ปุ่ม สูง 44px · ตาราง: หัว 40px, ระยะใน cell 8×12, แถวสองบรรทัด 52–60px
- เงา: การ์ดที่วางนิ่งไม่มีเงา · เงาเฉพาะเมนูลอย (กลาง) และ dialog / toast (สูง)

### 2.4 กติกาที่ต้องรักษา

1. สีคู่ข้อความเสมอ — ห้ามสื่อสถานะด้วยสีอย่างเดียว
2. cobalt ใช้เฉพาะปุ่มหลัก / รายการที่เลือก / ลิงก์ / focus
3. หนึ่งหน้า (หรือหนึ่ง dialog) มีปุ่ม primary ปุ่มเดียว
4. ปุ่มที่กดไม่ได้ต้องบอกเหตุผล (tooltip หรือข้อความใต้ปุ่ม)
5. เครื่องมือต่อแถว 3 อันขึ้นไป ยุบอันรองเข้า `•••` · ปุ่มลบแยกจากปุ่มปกติ
6. ตารางกว้างเกินให้เลื่อนในกรอบตาราง ห้ามทั้งหน้าเลื่อนแนวนอน
7. skeleton ตาม layout จริง · "ยังไม่มีข้อมูล" ≠ "ไม่พบตามตัวกรอง"
8. สำเร็จ = toast · ล้มเหลว = toast + แถบแจ้งเตือนค้างบนหน้า
9. เป้ากดอย่างน้อย 44px บนจอสัมผัส
10. วันเวลาเป็นเวลาไทย ปี พ.ศ. · ในตาราง `26/10/69 12:35` · ในหน้ารายละเอียด `26 ต.ค. 2569 12:35` · ระยะเวลา `1:38:54`

## 4. บทบาทผู้ใช้

ทุกบทบาทบน web เห็นข้อมูลทั้งบริษัท · หัวหน้าทีมเห็นเฉพาะทีมของตัวเองในแอปมือถือ

| บทบาท | ช่องทาง | ใช้ทำอะไร |
|---|---|---|
| ผู้ดูแลบริษัท (Company admin) | Web | **ใช้ฟังก์ชันหลักได้ครบทุกอย่าง** — ติดตามกล้องบนแผนที่, ประวัติเส้นทาง, ภาพสดหลายจอ + talk, ใบงาน, วิดีโอย้อนหลัง + ดาวน์โหลด, รับทราบและปิดเรื่องแจ้งเตือน · และจัดการพนักงาน, ผู้ใช้ระบบ, ผู้ใช้จาก Entra · ดูตารางสิทธิ์ของแต่ละบทบาท |

- **ตัวอย่างแจ้งเตือนระดับเตือน** ใช้สองรายการนี้ทั้งในกระดิ่ง หน้าเต็ม และ panel "ต้องดูแล" บนแดชบอร์ด

  - "BWC-0044 มีวิดีโอ 35 นาทีที่ยังไม่ผูกกับใบงาน" — ระบบแจ้งเมื่อการใช้งานกล้องที่ยังไม่ผูกกับใบงานมีวิดีโอรวมอย่างน้อย 30 นาที
- **ปุ่มรายรายการ** แยก "รับทราบ" กับ "ปิดเรื่อง" สำหรับผู้ดูแลบริษัทและผู้ปฏิบัติการ

| สถานะรายการ | ปุ่มที่แสดง | ผลเมื่อกด |

- **Frame:** รายการลอยจากกระดิ่ง · หน้าเต็ม (ผู้ดูแลบริษัท / ผู้ปฏิบัติการ) แสดงตัวอย่างสถานะใหม่และรับทราบแล้ว · หลังปิดเรื่อง แสดงรายการเป็น "แก้ไขแล้ว" ในตัวกรองสถานะที่ตรงกัน · มุมมองผู้ดูข้อมูล แสดงรายการและสถานะโดยไม่มีปุ่มรับทราบหรือปิดเรื่อง
